# Get secure fast — rust-core (C ABI)

`rust-core` is the shared trust core that the Android, iOS, macOS, and Windows
SDKs are built on. Most integrators should use a **platform SDK** instead — see
the per-platform quickstarts under [`sdk/`](../). This guide is for embedding
the C ABI directly (a new platform binding, or a C/C++/Rust host).

## Requirements

- Rust **1.74** or newer (toolchain pinned by `rust-toolchain`).
- The generated header [`kseal-ffi/include/kseal.h`](kseal-ffi/include/kseal.h)
  (regenerated by `cargo build`; never edit by hand).

## 1. Build the library

```bash
# Host shared library (for tests / desktop bindings):
cargo build -p kseal-ffi            # → target/debug/libkseal_ffi.{so,dylib}

# Each platform SDK ships a convenience wrapper that runs the above and stages
# the header + host lib into that SDK, e.g. for iOS:
../ios/scripts/build-rust-host.sh
```

The release profile is `panic = "abort"` + LTO + stripped, so a panic can never
unwind across the C ABI.

## 2. Create a core and evaluate risk

```c
#include "kseal.h"

KsealCoreHandle *core = kseal_core_new(
    config_pubkey, 32,   // Ed25519 public key for signed configs
    proof_key, 32,       // instance HMAC key (hardware-bound in production)
    /*platform*/ 0, /*max_batch*/ 0, /*risk_window*/ 0, /*zstd_level*/ 0);
if (!core) { /* bad key arguments */ }

uint32_t score; int32_t confidence;
KsealStatus st = kseal_evaluate_risk(core, risk_bits, &score, &confidence);
```

Passing `0` for the tuning parameters selects the audited core defaults.

## 3. Branch on the typed status

Every call returns a `KsealStatus`: `Ok` (0) on success, or a distinct negative
code per failure cause. The platform SDKs map these one-to-one onto their typed
error taxonomies (`KsealErrorKind` / `KsealErrorCode`):

| `KsealStatus`  | value | meaning                                   |
|----------------|-------|-------------------------------------------|
| `Ok`           | `0`   | success; any `out` parameter was written  |
| `ErrNull`      | `-1`  | a required pointer argument was null      |
| `ErrDecode`    | `-2`  | a protobuf payload failed to decode       |
| `ErrInvalid`   | `-3`  | invalid argument / rejected config        |
| `ErrCrypto`    | `-4`  | a cryptographic operation failed          |
| `ErrTransport` | `-5`  | serialization/compression failed          |
| `ErrPanic`     | `-6`  | internal panic caught at the boundary     |

## 4. Free what you own

Buffers returned via `KsealBuffer` out-parameters must be released with
`kseal_buffer_free`; the core handle with `kseal_core_free`. See the header for
the ownership contract on each function.

## ABI stability

The C ABI is **additive-only**: existing functions, the `KsealStatus` values,
and struct layouts never change meaning. New capability is added as new
functions. See [CHANGELOG.md](CHANGELOG.md).
